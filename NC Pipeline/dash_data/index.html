Choosing the cluster size

HDBSCAN was run at several minimum cluster sizes. The highlighted row was chosen: it matches the Raleigh pilot's coherence with the best diversity and a topic count a person can still review by hand.

How the topics were made

  1. Each review was cleaned as in the Raleigh pilot (lowercase, no punctuation, store names removed) and embedded with all-MiniLM-L12-v2.
  2. UMAP reduced the embeddings to five dimensions for clustering, and to two for this map.
  3. HDBSCAN found dense groups of reviews; reviews in no group are outliers.
  4. BERTopic described each group with its most distinctive words (c-TF-IDF), plus KeyBERT and MMR word lists.
  5. The closest Raleigh topic comes from Teresa's saved pilot model applied to the same reviews.

Source: NC master review database, freeze v2 counts. No labels were used at any step.
